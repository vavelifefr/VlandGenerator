# Границы проверки / 4

Проект хранит геометрию, каталог и программы zone/spawner. Готовые сущности в проекте отсутствуют. Время, AI, физику, смерть, подбор, добычу и события реализует принимающее приложение. Чистый JS-планировщик проверяет условия и предлагает команды, а host подтверждает фактическое создание.

Поддерживается только формат 4 без миграций. Некорректный авторский черновик можно сохранить для дальнейшей правки. Runtime-экспорт требует validation.ok и отклоняет невалидную карту или непригодную точную точку появления. Экспорт проекта сохраняет целостный черновик; PNG и diagnose доступны для исследования ошибок авторской навигации. Целостность документа и checksum проверяются отдельно. Пустая/несовместимая зона может давать предупреждение и нулевой результат.

Top-down проверяет клеточную связность и защищённые маршруты. Sideview использует ограниченную AABB-модель с заданными способностями и физическими параметрами. Это не универсальный navmesh или гарантия проходимости в любом движке. Host обязан проверить свою коллизию и навигацию до acceptedIds. Возможные будущие срабатывания не доказываются одним пробным снимком.

Авторские связи teleport/lift/stairs действуют внутри одного проекта между фиксированными однократными source-программами. Проверяются доступ от входа, безопасное прибытие и путь обратно; основной native-маршрут продолжает проверяться отдельно. Связи между внешними картами не моделируются. До 128 пар; физический поиск sideview ограничен 6000 опорами. resolveTransition проверяет фактически созданные концы, но не перемещает игрока, не проверяет его текущую позицию и живые препятствия, не исполняет стоимость. Это обязанность host. Защищённые native-переходы исполняются по данным провайдера.

Автоматическая изоляция применяется к Данжу и системе ярусов, максимум 4 независимых участка по 8 комнат на этаж. Без безопасного кандидата участок не создаётся. В одном этаже используются телепорты; лестницы/лифты требуют настоящего другого яруса с просветом от 2. Площадка 1–3 клетки на сторону не гарантирует проходимость всего мира крупным существом: стандартное доказательство — walker 1×1, собственный профиль проверяет host. Ярус с externalTransports отдельно не самодостаточен; нужен весь мир с worldLinkId, площадками и проверенной глобальной навигацией. Структурные fixtures не зависят от условий optional source-программ.

content/ не знает игровых целей: проверяет данные, ссылки, полный габарит, поверхность, среду, породы, глубину, метрики, опору, маску, занятость, расписание и лимиты. Не знает логики освещения, боёвки или поведения стаи. Representation — метаданные блока источника, его коллизию/разрушение обрабатывает host, при необходимости передавая occupied.

Плотность даёт детерминированную цель по подходящим якорям до текущей занятости и расстояний. Точный процент типов на малой выборке не гарантируется. Недобор не приводит к ослаблению правил. Цель фиксируется в state при первой допустимой попытке; изменение рельефа затем влияет на свободные позиции, но не пересчитывает сохранённую цель автоматически. Для новой цели требуется явно спроектированная смена программы/состояния.

Залежи соединены соседями топологии (4 на квадратной, 6 на гексагональной сетке), только ресурсы 1×1; quantity считает клетки ресурса. Минимальный размер пятна может делать остаток квоты невыполнимым. Запас amount — данные для host, а не симуляция геологии/экономики. «Рядом с рекой» требует маски или явного поля расстояния; имя сущности не добавляет скрытых условий.

Группы используют расстояние сетки; радиус спавнера — круг якорей на квадратах или область по гексагональному расстоянию. Планировщик не прогоняет пропущенные циклы, одна попытка на источник за вызов. Неактивные уровни/источники не исполняются, общая популяция всё равно учитывает их живых владельцев. Максимум одновременно живых включает ушедших за радиус.

Host должен сохранять даже пустой commit (активация/таймер), а state вместе с подтверждёнными объектами — атомарно или через идемпотентный журнал. Повторный createSpawnState при загрузке обнулит once, поэтому храните исходный state. Изменение программ/каталога под существующим state отклоняется. Автоматического переноса состояния на другую программу нет.

FNV fingerprints/checksum обнаруживают случайные изменения и устаревшие результаты, но не являются подписью против злоумышленника. Сервер для локальной доверенной работы, по умолчанию 127.0.0.1. Публичное размещение требует самостоятельной аутентификации, разграничения доступа и ресурсных квот.

Лимиты: 16 уровней, 250000 клеток/уровень, 500000 суммарно; 256 определений и источников, 16 правил/источник, 16 типов/правило; 12000 живых сущностей, число новых команд ограничено оставшейся ёмкостью; footprint 1–8; properties 8 KiB; JSON 24 MiB; 2 млн проверок/операцию и 60 секунд Worker. Большое число правил/областей может исчерпать бюджет: уменьшите задачу, частичного применения нет. UI Undo/Redo до 16 состояний, только текущая вкладка. Живое соединение страницы отслеживает закрытие; резервный таймер при недоступности соединения — 120 секунд. Рабочая сессия автоматически перезаписывается в одном .run/working-session.json; именованные проекты сохраняются явно.


Новая геометрия: коридоры допускают явно заданные 1–24 клетки; базовый диапазон 1–3 сохраняется. Большие диапазоны увеличивают размер карты и стоимость поиска. Проверяются полный габарит, двери и граф. Профиль архитектуры задаёт исходные параметры, а не гарантирует совпадение с референсным зданием.

Переходные биомы — поля расстояния и примесь соседнего цвета, не экологическая симуляция. transitionWidth задаёт предел на каждой стороне совместимой границы; вода/cliffs/snow/rocky-coast сохраняют резкий край. Основной biome определяет условия наполнения. Пользовательский основной RGB точный, поэтому его переопределение может визуально убрать примесь; цвет только вторичного биома участвует в смешивании. Ручная правка biome очищает примесь лишь в своей клетке без пересчёта соседей, материала и других полей. Отмена возвращает исходные данные.

Гауссов фильтр — обработка поля, не доказательство гидравлической эрозии. Профильная вода — статическое насыщенное заполнение выбранных рек/озёр до head=max(seaLevel+.04,filledElevation+.035), глубина rounded(clamp(head−bed,0,1)) (rounded — округление до шести десятичных знаков); дно и маска не изменяются ради этой отметки. lakes регулирует отбор впадин, а не частичную глубину выбранного озера. Это не динамика, расход воды, приливы или моделирование высыхания. Предел глубины1 означает, что произвольная синтетическая глубокая впадина может не вместить рассчитанный head без изменения дна; общую монотонность уровня для всех возможных полей обещать нельзя.

Priority-Flood относится к исходному heightmap. После навигационных ремонтов водная отметка — heightmap+waterDepth: elevation моста является высотой настила. Ручные правки высоты/воды не перезапускают hydrology, биомы или соседние поля; проверка навигации не превращает их в регенерированный водосбор. riverWidth=N ограничивает расширение ядра N−1 кольцами, но не гарантирует точную полную ширину; малые озёра фильтруются до выбора окончательных речных цепей только в профильной ветке. Истоки выбираются по относительной высоте своей сухой компоненты и достаточному дождевому стоку; конкретное число рек и слияний на любом seed не обещается. Боковые рукава ограничены низиной, размером карты, радиусом и возвратом в существующую сеть ниже; их маска может визуально совпасть с широким руслом. Отдельная дельта у каждого устья не гарантируется, основным направлением остаётся один flowTo.

Связанный рост островов/континента использует анизотропный евклидов потенциал с положительными весами и предшественниками. Он уменьшает характерный ромбовидный рисунок суммы квадратных шагов; дискретизация square/hex всё равно влияет на форму, особенно на малых размерах. В новом каркасе ствол/ветви, сглаженные окончания и ограниченные береговые врезы разрешаются в зависимости от меньшей стороны карты;50 проще300, но «сложнее» не означает одинаковое число ветвей каждого острова, конкретное число бухт или равную пригодную площадь. Разные роли островных ядер сохраняют и сложные, и более широкие участки суши; это не геологическая симуляция или гарантия удачного контура для любого seed. Гарантия полностью независимого от сетки контура отсутствует.

«Ландшафт» (landscape) использует только square; «Гексагональный ландшафт» (hexlandscape) — только hex. Пещеры и рельеф (caves/relief) сохраняют выбор обеих сеток. Несоответствие mode и topology отклоняется при генерации и импорте; преобразования прежнего landscape-hex проекта в новый режим нет. Оба раздела ландшафта используют общий генератор, редактор и стопку физических слоёв. Геометрия гексагонов: pointy-top odd-r, 6 соседей. Габарит крупного тела остаётся прямоугольной маской offset-строк. Контуры, заливка и ресурсная связность учитывают топологию; автоматического произвольного поворота моделей нет. Поселения — один квадратный слой с улицами и доступными контурами участков; городская экономика, история, жители и полноценный архитектурный CAD не реализуются этим режимом.

Профили landscape:{structure,baseBiome,biomes:[{id,type,percent}]} работают только в landscape/hexlandscape. До64 повторяемых карточек; проценты от сухой поверхности после гидрологии, до навигационных ремонтов/ручных правок; сумма<=100, остаток основному. Процент территории включает природные подтипы и не равен гистограмме tileID. Изменение карточек не меняет рельеф/реки. Это процедурная статическая модель, не климатическая/геологическая симуляция. Подробный контракт и атомарные конфликты пересчёта — [API.md](API.md).

Природные стороны16–300, общий atlas-бюджет98304 по всем физическим срезам.300²=90000 допускает одну поверхность; обязательные два и более среза caves при300² превышают бюджет. Размер и число слоёв не уменьшаются автоматически.50/100/200/300 — обычные width/height, не новая единица масштаба. Большие карты всё ещё ограничены временем Worker, JSON-бюджетом и возможностями устройства.

Пониженные дополнительные провинции отводятся долиной по исходному ацикличному графу стока к морю/границе **до** окончательной hydrology. Это геометрическая подготовка рельефа, а не симуляция водной эрозии, сезонного болота или гарантия отсутствия любого озера. Высоты/климат дополнительных территорий влияют на окончательные осадки/водосбор; ручной выбор не означает независимую от природы заливку цвета.

PNG — RGB8 на канал + alpha8 (color type6). По слою до 16 млн выходных пикселей, JSON API до 16 MiB PNG суммарно. Весь выбранный набор проверяется до построения растров; лимит API не применяется к прямой записи файлов из UI. Режим «Все слои» браузера использует выбранную папку при наличии File System Access API; иначе применяются ограничения браузерных загрузок. Экспорт не подтверждает физическую корректность сам по себе — вызывайте validateProject.

Рабочая сессия: один JSON, 16 вкладок, 24 MiB на режим, 64 MiB всего; атомарный .tmp только на время записи. Закрытие всех вкладок и новое открытие очищают её, аварийный клиент истекает через 2 минуты, перезапуск сервера не восстанавливает старый файл. Это не резервная копия: для постоянных карт нужен явный project-save. История отмены, незавершённый полигон и модальные черновики между страницами не переносятся.
