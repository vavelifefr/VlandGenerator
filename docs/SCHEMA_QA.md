# Проверка JSON Schema

Приложение запускается с Node.js20+ без установки пакетов. Для дополнительной проверки схем разработчику нужен Python и необязательный пакет jsonschema. Он устанавливается в отдельное служебное окружение, вне папки проекта. Браузер, сервер, CLI и модуль content/ этот пакет не используют.

## Подготовка окружения

Команды выполняются из корня VlandGenerator и совместимы с Windows PowerShell5.1. В примере окружение создаётся в пользовательской папке LocalAppData. Активация окружения и изменение ExecutionPolicy не нужны: вызывается его python.exe напрямую.

```powershell
python --version
$schemaQaDirectory = Join-Path $env:LOCALAPPDATA 'VlandGenerator\SchemaQA'
python -m venv $schemaQaDirectory
if ($LASTEXITCODE -ne 0) { throw 'Не удалось создать окружение проверки схем.' }

$schemaQaPython = Join-Path $schemaQaDirectory 'Scripts\python.exe'
& $schemaQaPython -m pip install -r tools/schema-qa-requirements.txt
if ($LASTEXITCODE -ne 0) { throw 'Не удалось установить пакет проверки схем.' }

$env:VLAND_SCHEMA_PYTHON = $schemaQaPython
```

Версия jsonschema закреплена в [schema-qa-requirements.txt](../tools/schema-qa-requirements.txt). Установка может обращаться к реестру пакетов; последующая проверка схем разрешает ссылки через локальный Registry (реестр загруженных схем) без загрузки схем из сети. Переменная VLAND_SCHEMA_PYTHON действует только в текущем процессе PowerShell и запущенных из него командах.

## Проверка текущего проекта

Сначала создайте свежие контрольные документы, затем запустите валидатор:

```powershell
node tools/verify-content.mjs
if ($LASTEXITCODE -ne 0) { throw 'Проверка содержимого завершилась с ошибкой.' }

node tools/verify-schema-instances.mjs
if ($LASTEXITCODE -ne 0) { throw 'JSON Schema проверка завершилась с ошибкой. См. evidence/schema-instances.json.' }
```

Повторная установка пакета не требуется. В новом окне PowerShell достаточно снова задать VLAND_SCHEMA_PYTHON, указав python.exe существующего окружения.

[verify-schema-instances.mjs](../tools/verify-schema-instances.mjs) собирает реальные рецепты, проекты, документы для приложения, LLM-контексты, PNG-ответы, задания экспорта, native-снимки, источники, правила и результаты предварительных проверок. Документы с наполнением берутся из свежего прогона verify-content. Авторские пары переходов и автоматические связи создаются вызовами существующих примеров в памяти. Рабочая сессия создаётся в собственной временной папке и удаляется после чтения. Пользовательские проекты, авторские примеры и живая .run не изменяются; живая сессия не читается.

Основной результат — [schema-instances.json](../evidence/schema-instances.json): версии валидатора и стандарта, число проверок, список документов и ошибок с путями к полям. schema-instance-data.json рядом с ним содержит входы текущей проверки. Отчёты перезаписываются под стабильными именами.

## Что подтверждает результат

Проверки выполняются для JSON Schema Draft2020-12 и разделены по назначению:

- Проверка метасхем подтверждает корректность описаний схем из schemas/ и engine/schemas/.
- Проверка экземпляров подтверждает соответствие выбранных реальных документов этим схемам. Локальный реестр разрешает ссылки между файлами.
- Отрицательные контрольные примеры удаляют обязательное верхнее поле из подходящего корректного документа. Такой документ должен быть отвергнут; это проверяет, что валидатор действительно применяет требования схемы.
- Семантические JS-валидаторы проверяют смысл данных: контрольные суммы, ссылки, геометрию, маршруты и программы появления. JSON Schema не заменяет эти проверки и не подтверждает физику принимающего приложения.

Текущий стандартный прогон jsonschema4.26.0:60схем,381документ,348отрицательных контролей,8режимов. Отдельный Surface-прогон проверил8реальных документов300×300 и8контрольных отказов. Это покрытие конкретной выборки, а не доказательство корректности всех возможных входов. Актуальные числа и ошибки смотрите в отчёте; состав документов меняется вместе с проектом.

## Профили ландшафта

Дополнительная матрица проверяет4основы ×7биомов ×2режима и готовит98документов:56рецептов и по14проектов, runtime и LLM-контекстов. Прогон использует собственное временное окружение HTTP/CLI и не сохраняет именованные проекты.

```powershell
node tools/verify-landscape-profiles.mjs
if ($LASTEXITCODE -ne 0) { throw 'Проверка профилей завершилась с ошибкой.' }
& $env:VLAND_SCHEMA_PYTHON tools/verify-evolution-schemas.py --data evidence/landscape-profile-schema-data.json --report evidence/landscape-profile-schemas.json
if ($LASTEXITCODE -ne 0) { throw 'Схемы профильных документов не прошли проверку.' }
```

## Переносимая копия

При заданной VLAND_SCHEMA_PYTHON обычная команда дополнительно проверяет схемы на независимой копии проекта:

```powershell
node tools/verify-portable.mjs
if ($LASTEXITCODE -ne 0) { throw 'Проверка переносимой копии завершилась с ошибкой.' }
```

Внутри копии заново создаются контрольные документы и выполняется тот же JSON Schema прогон. После успешного выполнения создаётся evidence/schema-instances-portable.json; evidence/content-portable.json отмечает jsonSchemaInstances и число документов. Без VLAND_SCHEMA_PYTHON дополнительные Python-проверки пропускаются, а обычные Node/CLI/HTTP проверки продолжают работать. Такой прогон нельзя называть полноценной проверкой экземпляров JSON Schema.

Отдельно выполняйте `node --test`, проверку содержимого и браузерные проверки по изменению. Критерии проекта описаны в [EXTENDING.md](EXTENDING.md) и [LIMITATIONS.md](LIMITATIONS.md).

## Проверка Surface и карточек биомов

`node tools/verify-landscape-surface.mjs` проверяет32синтетические карты (две сетки,50/100/200/300,четыре формы), повторяемые карточки, JS/HTTP/CLI и готовит8реальных документов300×300. При заданной VLAND_SCHEMA_PYTHON они проверяются полной JSON Schema. Контактлист: evidence/landscape-surface-preview.html. Пакетные веса биомов и доли проверяются отдельно от гистограммы конечных tileID.

Численный контроль запускайте Python существующего окружения: `& $env:VLAND_SCHEMA_PYTHON tools/test-schema-percentages.py`. Он проверяет десятые доли, включая0.3, без ошибок двоичного округления; целое32.0 остаётся допустимым целым,32.5не становится целым. Основной Python-валидатор читает дробные значения через Decimal.

Браузерный контроль `tools/verify-surface-browser.mjs` использует только уже установленный служебный Playwright: укажите путь к его index.mjs в VLAND_PLAYWRIGHT_MODULE и выполните `node tools/verify-surface-browser.mjs`. Скрипт ничего не устанавливает, запускает отдельный headless-браузер и независимый контекст/серверную копию для каждого сценария, чтобы не смешивать их в одну64MiBсессию; пользовательский профиль и сервер9670 не используются. Проверяются1100/360px, обе сетки и размеры до300. Это программная проверка формы/Canvas, не физический телефон и не художественное принятие результата пользователем.

`node tools/verify-surface-portable.mjs` проверяет свежую копию вне проекта, полный Node-набор и синтетические JS/HTTP/CLI операции Surface; отдельного хэш-аудита авторских examples/fixtures нет. Итоговые отчёты: evidence/landscape-surface-portable.json и landscape-surface-browser.json. Ошибки/промежуточные FAIL записываются честно; наличие инструмента не означает PASS.
