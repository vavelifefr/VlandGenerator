# Обслуживание и очистка

Пользователь разрешил изменять документацию и удалять подтверждённо устаревшие документы, временные файлы и ненужные результаты. Хранить не больше двух версий для отката; не собирать всю историю разработки. Это ограничение количества копий, а не требование создавать две копии после каждого этапа.

## Что сохранять

- Рабочие исходники, тесты, схемы, инструменты и текущую документацию.
- Авторские данные, fixtures (контрольные входные данные), примеры и именованные проекты.
- Живую `.run/working-session.json`, файлы действующего сервера и настройки пользователя.
- Входы действующих проверок. Например, `evolution-contract-data.json`, текущие `content-*-schema-data.json`, образцы проектов автоматических переходов и `map-linking-browser.json` используются инструментами и не являются rollback-копиями.
- Последний пригодный отчёт каждого вида; предыдущий — только если нужен для сравнения. Не накапливать датированные копии одного отчёта.

## Документация

Текущая точка продолжения — [work/CONTEXT_STATE.md](../work/CONTEXT_STATE.md). [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md) описывает текущее поведение и границы проверки. `work-status.json` содержит машинный статус. Завершённые рабочие заметки не заменяют эти файлы и могут удаляться после переноса нужных фактов.

После каждого этапа проверять или запускать сервер и открывать [главную](http://127.0.0.1:9670/) в Codex для оценки пользователем. Не управлять содержимым его вкладок без отдельного согласия.
