# Контракт зон и спавнеров / 4

## Документы и границы ответственности

Project: `vland.project/4` содержит recipe, исходную геометрию source, актуальный catalog, sources[], transitions[] (необязательный массив связей), edits[], revision и checksum. В нём нет массивов готовых сущностей, прежних zones/instances, подавлений или запечённых результатов.

Recipe: `vland.recipe/4` описывает новую геометрию и каталог. generation не принимает настройки наполнения. Native source имеет собственную версию конкретного генератора; это не формат авторских сущностей.

Runtime: `vland.runtime/4` содержит нейтральную scene `{map,catalog,sources}`, пустое initialState, ссылки и навигацию. Геометрические fixtures — обязательные переходы/механизмы основы. Их нельзя использовать как обход системы наполнения; произвольный сундук, моб или растение появляется через sources.

State: `vland.spawn.state/4` — отдельное сохраняемое состояние принимающего приложения. Содержит подтверждённые entities, счётчики правил и источников, часы, список отключённых источников, revision и checksum.

Plan: `vland.spawn.plan/4` — предложение появления с привязкой к сцене и state. Host создаёт допустимые команды, затем commit принимает их ID. Неподтверждённые команды не расходуют лимиты. Между авторским проектом и живым состоянием нет неявного копирования результатов.

## Каталог

Шесть категорий: objects, items, resources, flora, fauna, events. Определение содержит id/name/category/type/subtype, цвет/символ, footprint, blocking, channel, constraints и properties. Уникальный ID — латиница с цифрами, дефисами, подчёркиванием, 1–64 символа, начинается с буквы. Служебные prototype-имена запрещены.

Категория отвечает за смысл и UI, канал — за совместимость занятости. Каналы: solid, prop, actor, cover, subsurface, air, trigger. Blocking/канал и полный габарит проверяются независимо. Properties каталога — базовые данные приложения; command.properties дополняют их (например amount/depositId ресурса). Host объединяет их при создании.

## Источник

У зоны и спавнера одинаковые rules/schedule/conditions/limits и формат origin. Различается только kind/area; representation применима к спавнеру.

- zone.area = `{mask:{encoding:'rle-rows-v1',runs:[[y,x,length],...]}}`. Все клетки габарита должны лежать внутри маски.
- spawner.area = `{x,y,radius}`. Радиус в клетках, круг по евклидовому расстоянию. Ограничивает якоря появления, а не весь габарит. Радиус 0 — ровно одна возможная координата якоря.
- layerId — ровно один существующий физический уровень. Для нескольких слоёв создаются несколько источников.
- seed — uint32. Больший priority планируется раньше; при равенстве порядок по id.
- origin = `{kind:'manual'}` или `{kind:'automatic',groupId}`. Ручная операция source.put/source.mask закрепляет manual.
- representation описывает необязательное представление источника в host. Не создаёт дополнительную сущность, не резервирует место и не задаёт физику. Host сам учитывает физический блок во внешней занятости.

## Правила

entries — 1–16 ссылок на определения одной категории с положительными относительными весами. Нельзя смешать флору с фауной в одном источнике; для совместного события создайте связанные источники и общий сигнал приложения.

quantity.mode count выбирает целую цель в min..max по seed. density задаёт цель round(число подходящих якорей × density / 100), ограниченную min..max. Подходящие якоря считаются по статической геометрии и обязательным fixtures, до текущей занятости и расстояний. Цель фиксируется в state при первой допустимой попытке.

generator: scatter / groups / deposits. Deposits — только resources с габаритом 1×1, количество означает клетки ресурса. group задаёт размер групп и радиус, deposit — размер связного пятна и запас клетки. Поля присутствуют и при другом generator, но применяются только соответствующей стратегией. Шаг использует Манхэттена между ближайшими клетками габаритов. Chance решает, включено ли правило целиком, стабильно по seed.

filters добавляет constraints сущности: списки поверхности/исключений/среды/биомов/уровней/видов уровней/пород, глубина, числовые диапазоны, требования опоры и свободного канала. Пустой список не ограничивает; false в правиле не отменяет true у определения. Отсутствующая требуемая метрика или порода означает отказ. Для sideview опора проверяется под полным габаритом.

## Расписание и условия

trigger load/enter/proximity/signal. Enter/proximity получают ID источников, signal получает signalId. Активация защёлкивается и сохраняется commit даже при ожидании ночи, питания или таймера.

repeat once/cycle. Once считает подтверждённые появления за всю жизнь и завершает квоту; смерть/подбор не обнуляет её. Cycle считает принадлежащие популяции живые сущности внутри области, пополняет цель партиями и соблюдает общий предел живых. Interval задаёт время до следующей попытки после текущей, delay — до первой. Clock seconds/turns, ходы целые. Пропуск времени не создаёт все пропущенные партии сразу.

conditions.timeOfDay any/day/night и flags [{id,value:boolean}]. Эти условия проверяются после активации. Host передаёт текущую фазу и флаги; сервер не определяет день/ночь сам.

## Лимиты и владение

maxAlive — предел одновременно живых, batchSize — предел одной циклической партии, total — предел за всю жизнь либо null. Уникальное владение хранится в entity.origin {sourceId,ruleId,index}. Существа за пределами области продолжают расходовать maxAlive; смерть/подбор освобождает этот лимит через updateSpawnState.removeIds, но сохраняет total.

Одинаковый populationId объединяет живых и накопленные появления нескольких источников. Категория, maxAlive и total должны совпадать. Циклическая цель правила считает общую живую популяцию с тем же ruleId внутри области; жёсткие общие пределы учитывают всех членов группы во всех уровнях. Для разных ролей в одной популяции используйте разные ruleId.

origin.index/sequence отличает каждое предложение, включая отклонённые, чтобы повторная попытка не получила ID частично подтверждённой прошлой команды. Счётчики created растут только по acceptedIds. Состояние не хранит отвергнутые объекты.

## Распределение

vland.distribution.request/4: groupId, layerIds, template (полный источник), placement {mode,count,density,minDistance}. Count/density здесь относятся к числу спавнеров на уровень. Для zone создаётся одна маска подходящих клеток на выбранный уровень. Delta содержит removeIds/sources/report; app-предпросмотр также связан с projectChecksum.

Замена затрагивает только automatic источники groupId на перечисленных layerIds. Manual сохраняются, коллизия стабильного ID с ручной правкой приводит к сохранению этой правки, report.preservedIds. Не следует вручную переключать origin для обхода этого правила: используйте editProject.

## Ограничения

16 уровней, 250000 клеток на уровень, 500000 суммарно; 256 определений и источников; 16 правил на источник, 16 типов на правило; 12000 живых сущностей и команд в плане с учётом уже живых; footprint 1–8; радиус источника 0–64; до 2 млн проверок в одной операции; 24 MiB JSON проекта/экспорта. Данные свойств ограничены 8 KiB. Области всех источников ограничены 2 млн клеток. Большая карта с множеством правил может исчерпать вычислительный бюджет; результат не применяется частично.

JSON Schema проверяет структуру; JS-валидаторы дополнительно проверяют ссылки, длины полей карты, отношения min/max, габариты и лимиты. Checksum/fingerprint обнаруживает устаревшие данные и случайные изменения, это не криптографическая подпись.

## Пары переходов

Автоматический доступ изолированных участков относится к геометрии, а не к authored sources. В Данже settings находятся в layout.transports, в ярусах — generation.autoTransports; изоляция выключена по умолчанию. Такие пары экспортируются в runtime.links с origin base / automatic true и в map.fixtures, без запекания необязательных сущностей. Обязательные площадки защищены от блокирующего наполнения. См. API.md для лимитов, типов, отчёта и различия local transportLinks / externalTransports / world.verticalLinks.

project.transitions — массив до 128 связей `{id,kind,fromSourceId,toSourceId,bidirectional,travelCost}`. Отсутствие массива означает отсутствие авторских пар. kind teleport/lift/stairs, стоимость 0–100000. Концы ссылаются на разные конкретные sources одного вида; один источник максимум в одной паре. Это метаданные связи программ, без прямых экземпляров. Схема — transition.schema.json; редактирование через transport.connect/disconnect. Направление и стоимость не относятся к расписанию появления.

Фиксированность точки требует load/once без задержек/условий, radius0, одного неблокирующего типа, scatter/count1/chance1. Связанные источники становятся ручными. Валидация app/ проверяет физическую доступность, пригодность прибытия и возврат; content/ остаётся независимым и исполняет только программы. Runtime.links экспортирует обе разрешённые точки, а resolveTransition проверяет их фактическое создание по подтверждённому state. См. API.md для полного контракта и границ native/author навигации.

См. [API.md](API.md), [USER_GUIDE.md](USER_GUIDE.md), [LLM_GUIDE.md](LLM_GUIDE.md). Ранее существовавшие форматы, прямые экземпляры и API-алиасы отсутствуют.

Автоматическое распределение ограничено category + kind + groupId + layerIds. Даже одно имя группы у разных категорий не допускает перезапись. ID автоматического источника включает категорию и вид. Seed наполнения независим от seed основы. Обязательные транспортные точки изолированных комнат относятся к защищённым fixtures основы; необязательные portal/lift/stairs создаются обычными source-программами и содержат properties.transport для приложения.
