# Расширение VlandGenerator 4

## Слои ответственности

engine/ содержит независимые генераторы. app/ адаптирует снимки к проекту и нейтральной карте, защищает навигацию, хранит явные правки. content/ содержит каталог, маски, совместимость, распределение программ и чистый runtime-планировщик. Web/HTML/ui/ — общий редактор восьми страниц, формы, Canvas и Worker. server.mjs/cli.mjs используют execute из app, без своей версии алгоритма.

content/ не должен импортировать app/, engine/, Node, DOM, сеть или зависимости. Нельзя сохранять runtime-сущности в авторский проект. Модель zone/spawner одинакова для всех категорий, категорию нельзя превращать в отдельную ветку исполнения.

## Каталог и поля

Добавьте определение через данные defaultCatalog или операцию catalog: category/type/subtype, габарит, канал, blocking, constraints, properties. Не добавляйте особый объект type spawner со своим старым подформатом: source.kind уже решает эту задачу. Видимый блок спавнера — representation, а выпускаемые типы — entries правил.

Для новой метрики добавьте row-major поле в map.layers.metrics и подпись в Web/HTML/ui/constraint-model.mjs. Неизвестные метрики должны отвергать позицию. Новая среда требует согласованного изменения taxonomy, map.environmentAt, validateConstraints, формы и схем. Пользовательский числовой ID можно использовать без новой встроенной метрики, если внешняя карта его предоставляет.

constraints/filters редактирует Web/HTML/ui/constraint-editor.mjs; модель формы сохраняет отсутствие поля, false, ноль и пользовательские значения. Не дублируйте форму отдельно по режимам. Фильтр правила только сужает требования каталога.

## Новый режим генерации

Создайте provider в app/modes и запись MODES, загрузчик provider, generation-схему, renderControls и страницу через workspaceTemplate/build-pages. landscape и hexlandscape используют общий природный генератор и редактор с независимыми обёртками фиксированной сетки: square и hex. caves/relief сохраняют выбор обеих сеток. Проверка mode/topology обязательна и на генерации, и при импорте native request/слоёв; не форкайте hydrology, navigation, renderer или content для hexlandscape. Не вводите алиас или скрытое преобразование прежнего landscape-hex проекта. Адаптер возвращает build/validate/layers. layers должен возвращать независимые массивы, объекты основы помечаются origin source и структурными свойствами.

buildBase отключает необязательное native-наполнение до адаптации, сохраняя переходы, обязательные механизмы, защищённые маршруты и физику основы. Исходный снимок не меняется при редактировании содержимого. Общий редактор source-программ используется без форка. Проверяйте supports/gravity, reserved и навигацию нового режима отдельно от геометрической совместимости content/.

## Новый рисунок появления

Расширяйте rule.generator вместе с normalizeSource, схемами, формой правила и spawnRule. Каждая позиция проходит checkPlacement полного footprint и spacingFits с актуальной занятостью. Уважайте mask для зон, только область якорей для спавнера, reserved для блокирующих объектов и 2-миллионный бюджет. Количество всегда считает создаваемые сущности/ресурсные клетки, не меняйте единицы в зависимости от рисунка.

Результат — предложения команд. origin {sourceId,ruleId,index}, ID/случайность детерминированы seed и sequence/attempt. Не расходуйте created до acceptedIds. Сохраняйте причины недобора, а не ослабляйте фильтры. План должен повторно пересчитываться при commit и отвергать изменённую сцену/состояние.

## Runtime-адаптер

Host читает runtime.scene, строит геометрию/links/navigation, сохраняет initialState один раз, вызывает planSpawns в своём цикле и commitSpawnPlan с фактически принятыми командами. Map.fixtures — механика геометрии; необязательное наполнение — sources. Properties каталога объединяются с command.properties. Host передаёт монотонные часы, активации, фазу, флаги и внешнюю occupied.

Держите один актуальный state либо явно разделённые непересекающиеся популяции; два независимых state одного уровня нарушат общие лимиты. Сохранение ID живых сущностей и state делайте атомарно или через идемпотентный журнал. Движение/смерть сообщает updateSpawnState, отключение — disabledSourceIds. Не обнуляйте once после загрузки или подбора предмета.

Редактор проверяет native навигацию пробных команд. Host проверяет собственную физику до подтверждения. Представление физического блока спавнера и его коллизию реализует host; occupied учитывает такой блок, а разрушение отключает источник.

## Переходы между точками

Контракт project.transitions и операции transport.connect/disconnect находятся в app/transitions.mjs. Общая доступность и возврат — app/transition-navigation.mjs, живое разрешение — app/transition-runtime.mjs. UI связывания и выбора яруса едины для всех страниц; линии рисует Web/HTML/ui/map-transitions.mjs. Каталог задаёт вид и параметры по умолчанию, конкретное назначение хранится в связи источников. Не записывайте ID парной точки в общее определение каталога.

Новый provider должен отдавать реальные layerId, spawn/exit, обязательные links и безопасные физические клетки. Native переходы отображаются как защищённые связи основы. Для нового физического режима расширяйте доказательство подхода/прибытия/возврата, а не считайте произвольную точку доступной. Без фактического подтверждения обеих source-сущностей host не должен включать авторскую связь. Добавьте тесты одностороннего тупика, полного габарита, уничтожения/отключения точки, сохранения и повторного распределения.

Автоматическая изоляция: engine/core/transports.mjs выбирает непересекающиеся компоненты и сохраняет основной путь; transport-settings.mjs задаёт строгий контракт. engine/api/world-transports.mjs заменяет доступ выбранным вертикальным видом и резервирует реальные площадки. externalTransports — требования внешнего доступа, не скрытый телепорт. validateWorldLayer проверяет геометрию в контексте заявленных требований; публичный validateWorld отдельно доказывает реальные пары и глобальную навигацию, поэтому один внутренний отчёт слоя не подтверждает мир. App повторяет проверку по отредактированным клеткам и планируемым препятствиям.

Настройки интерфейса и API используют те же поля. Новые схемы дополняет tools/build-transport-schemas.mjs, вызываемый build-schemas. Обязательные точки нужно резервировать до планирования врагов, условных зон и среды. Для root-приложения buildBase сразу отключает необязательный native-контент; авторские категории исполняются независимо. Регрессии: tests/automatic-transports.test.mjs, tools/verify-auto-transports.mjs, Web/HTML/qa-auto-transports.html и независимая копия.

Локальные схемы создаются build-schemas; страницы/документация — build-pages. Используйте проверку JSON Schema и семантические JS-валидаторы вместе. ## Поля геометрии, сессия и ресурсы редактора

Новые поля проходят всю цепочку: native provider → views/sourceFields → materialize overrides → contentScene → runtime и JSON Schema. Добавляя числовую метрику, включите её в metrics (до 32), строковую — в явный контракт слоя. Не оставляйте дополнительные биомы/геоморфологию только в окраске canvas. Метаданные улиц/участков поселения экспортируются в runtime.navigation.

Для ручного материала сохраняются trait, физическое frozen/support и теги ограничений. Палитра, canvas и PNG используют cellColor. terrain.stroke атомарен; защищённая клетка отменяет весь геометрический штрих. Гексагоны используют pointy-top odd-r, шесть соседей и согласованные радиусы. content/topology независим от engine; тест сверяет соседей обоих модулей.

Web/HTML/ui/controls синхронизирует реальные значения полей перед генерацией/сохранением, включая ввод без blur/change. Дробные параметры допускают любое допустимое значение диапазона; checkbox false не становится невалидным из-за required. При смене категории сохраняйте текущий корректный черновик, при восстановлении сессии не перезаписывайте его старыми DOM-значениями. Не разрешайте действия редактора до завершения восстановления; общее меню остаётся доступным.

Web/HTML/ui/session и tools/session-store обслуживают один bounded working-session.json; проектные файлы сохраняются только явно. Все изменения файла проходят общую очередь и один фиксированный .tmp. Не добавляйте timestamp autosave/history на диск. Долговременные Undo-архивы и автоматическая загрузка старой сессии после перезапуска сервера противоречат принятому поведению. QA-отчёты имеют постоянные имена; переносимая копия удаляется в finally.

Новые проверки: evolution.test, session.test, tier-drafts.test; tools/verify-evolution.mjs; Web/HTML/qa-navigation.html и Web/HTML/qa-evolution.html desktop/360px. Python-проверка JSON Schema использует jsonschema/referencing только как инструмент разработки; Node-сервер и утилита этих пакетов не требуют.

## Размещение Web и генерация HTML

`Web/index.html` — главная; `Web/HTML/*.html` — редакторы, настройки, гайды и QA; `Web/HTML/ui/` — браузерные модули, стили и Worker. `Web/start.cmd`, `Web/stop.cmd` вызывают соседний `Web/server-control.ps1`; корень проекта вычисляется как родитель Web. Общие app/content/engine, сервер, CLI, схемы и исходные Markdown остаются в корне.

Сборщики `tools/build-pages.mjs` и `tools/build-docs.mjs` используют `Web/HTML/ui/paths.mjs` для адресов страниц, ресурсов, query и hash. Меняйте исходники сборщиков, а не только готовые HTML. Внешние и внутристранничные ссылки сохраняются; локальные браузерные пути начинаются от корня HTTP-сервера. Импорты общих модулей из ui идут через `../../../app/`, `../../../content/`, `../../../engine/`; запросы API — через `/api/`, примеры — через `/examples/`.

## Интеграция профиля поверхности

Публичный профиль landscape/hexlandscape: `landscape:{structure,baseBiome,biomes:[{id,type,percent}],landPercent,coastErosion,uniformity}`. Нормализатор `normalizeLandscapeProfile` сохраняет порядок и ID карточек, проверяет уникальные непустые ID до64 символов, тип из семи вариантов, максимум64 карточки и проценты0–100 с шагом0.1 при сумме не выше100%. Повторные типы, включая основной, разрешены; нулевая карточка не занимает площадь. Основной биом заполняет остаток, удалённая доля возвращается ему. Не добавлять старые формы, алиасы или миграции. Новые поля проходят native request, recipe, context, UI и JSON Schema. См. [API.md](API.md) и [LANDSCAPE_SURFACE_PLAN.md](../work/LANDSCAPE_SURFACE_PLAN.md).

`surfaceFields` в `engine/core/atlas-landforms.mjs` сохраняет многоуровневые шумовые поля Surface: крупный и региональный рельеф, местные детали, domain warp, сглаживание и термальную релаксацию. После них `landscapeElevation` применяет выбранную геометрию моря/суши, сохраняя амплитуду сухого рельефа; `landscapeClimate` задаёт широкую вариативность температуры и влажности вокруг основного биома. Для вулканической основы предусмотрен высотный конус с кратером. После `landscapeElevation` нельзя повторно применять квантильный sea-shift или старый `landforms.pattern`: это разрушит выбранные границы. Затем вычисляются орографические осадки и `surfaceWater`, и только после окончательной водной маски — территории биомов. Без профиля native Surface остаётся самостоятельной веткой.

При меньшей стороне больше32 `geologicalGeometry` в `landscape-profile.mjs` строит непрерывный геологический потенциал с многомасштабным искажением координат. Islands использует три самостоятельных асимметричных тела с seed-вариацией пропорций, изгиба, смещения и крупных выступов. Seed выбирает параллельное расположение с порогом2%, в остальных случаях — смещённое; водные проходы не обязаны сходиться в центре. Для смещённых тел при landPercent>=60 усилены широкие береговые бухты и защита от прямого среза рамкой при максимальной эрозии; редкая параллельная геометрия сохранена. Частота проверяется по реальным силуэтам, а не повторением формулы выбора. Конкурируют собственные непрерывные потенциалы тел, а не фиксированные радиальные секторы. Разница потенциалов задаёт морской промежуток: его ширина плавно меняется региональным полем и отдельными широкими расширениями между соседними островами. Для сходящихся проходов расширение ограничено сильнее, чтобы сохранять пригодную толщину берегов. Число широких береговых бухт-кандидатов меняется по seed; оно не обещает точного числа видимых входов. Эрозия усиливает местную изрезанность, сохраняя крупную форму. Coast использует материковый градиент, непрерывные региональные и местные поля, наклон и ослабленное двумерное искажение координат. Seed задаёт одну широкую асимметричную региональную особенность — мыс либо бухту; её влияние исчезает при нулевой эрозии. Континент использует отдельный потенциал округлённого прямоугольника с морскими долинами, описанный ниже. Принудительного чередования знаков, периодических опорных узлов и набора узких трубок нет. Разрешение уточняет местный контур, но не увеличивает количество доминирующих особенностей. Minimax/priority-flood сохраняет связь с полностью сухой стороной побережья; противоположная сторона остаётся морской. Клеточная зубчатость не подменяет крупные особенности формы.

Minimax-рост от связного начала включает клетку только вместе с предшественником. Континент сохраняет один массив в морской рамке; islands — три раздельных ядра с разными пропорциями. landPercent integer1..99 default75 задаёт точную квоту round(width*height*percent/100). Рост принимает топологически простые клетки: суша сохраняет нужное число компонент, остаточное море остаётся связным. Невозможная квота явно отвергается; скрытого clamp нет. При высокой доле острова плотно упакованы с искривлёнными морскими разделителями. Морской зазор переменный; у рамки действует непрерывный барьер с непериодической шириной. Для сторон от80 и суши от60% до3 ограниченных стадий геометрического открытия убирают тонкие прибрежные придатки у проблемного острова; каждый последующий рост заново набирает точную общую квоту с прежним доказательством трёх островов/связного моря. На малых долях эта стадия не применяется. Защищённые ядра сохраняются. Ширина проливов измеряется поперечными сечениями между разными компонентами суши, без учёта внешнего моря и внутренних озёр; это клеточная геометрия, не физическая гидродинамика. Coast растёт от сухой стороны и сохраняет противоположную морскую. Пороговые площади относятся к исходной геометрической маске, до рек, озёр и навигационных ремонтов. На картах с меньшей стороной<=32 контур упрощён, но точная квота и связность также обязательны; land без моря и native Surface без профиля не используют морской каркас. Не заменять minimax-потенциал суммой сеточных рёбер: это меняет фронт на square и делает форму ромбовидной. Проверять форму в физических координатах square/odd-r отдельно от окончательной проходимости.

`landscape-uniformity.mjs` задаёт общий пространственный масштаб 2**((50-uniformity)/45) для рельефа, климатических полей и влияния карточек. Среднее50 сохраняет прежний Surface; native caves/relief без профиля не меняются. atlas-water выбирает истоки из высоких клеток с достаточным стоком: низкая равномерность группирует подходящие бассейны, высокая предпочитает разнесённые истоки и другие бассейны. Направления flowTo/DAG и бюджет истоков сохраняются. Настройка не меняет геометрию моря, квоты карточек, rivers0 или выбор типов игроком.

Луга и леса имеют разные поля формы при прежних квотах: луговое поле сильнее сглаживается, лесное включает непрерывную локальную вариацию опушки с длиной детали не меньше нескольких клеток. При baseBiome=forest и выбранных meadow лес также выделяется своей формулой, а поляны зависят от стабильных ID луговых карточек. Не подменять это клеточным шумом, удалением квот или автоматическим выбором других биомов.

В material/biome-каналах природная клетка с согласованными biome/material использует дискретный общий цвет biome через `terrainBiomeColor` в app/display-colors.mjs. Для forest/taiga/rainforest общий тёмный зелёный, для plains светлый зелёный; именованные переходы имеют свои цвета. Явный material override остаётся точным RGB; ручной другой материал не подменяется цветом биома. `terrainLegendEntries` возвращает те же фактические цвета и объединяет стандартные лесные подтипы в одну запись. `secondaryBiome/transitionStrength` не смешивают RGB. Цветовые проверки: tests/biome-discrete-palette.test.mjs и tests/meadow-forest-colors.test.mjs; различие формы, площадь и крупные ядра: tests/meadow-forest-shape.test.mjs.

`applyLandscapeRegions` в `engine/core/landscape-regions.mjs` работает по клеткам с `waterType==='none'` после гидрологии. Квоты каждой карточки и основного остатка рассчитываются в десятых долях процента, округляются методом крупнейших остатков, затем суммируются по типу. Карточки дополнительных типов вносят независимые seed-поля на сетке17×17 узлов; их непрерывная интерполяция дополняет высоту, влажность, температуру и расстояние до воды. Каждый тип получает заданное количество наиболее пригодных доступных клеток; равноразмерные обмены на границе убирают одиночные фрагменты без изменения квоты. Один блок не обязан создавать один островок биома, несколько однотипных блоков могут сливаться.

Распределение не понижает территории и не прокладывает новые отводящие долины: высоты, русла и озёра на этой стадии неизменны. Общие климатические поля смешиваются через сглаженные цели всех территорий; масштаб сглаживания зависит от размера карты. Болота ранжируются по влажным низинам и близости существующей пресной воды; пустыня — по сглаженной сухости крупных областей; горы — по высоте и протяжённым гребням; снег — по холоду и высоте; вулканические области — по сухости, каменистости и высотной выпуклости. Снег выделяется перед горными территориями, чтобы сохранять холодные шапки. Если основной тип также ранжируется при выбранных лугах, его поле получает стабильное собственное влияние без дополнительной карточки. Это географические предпочтения, а не жёсткий запрет, который молча уменьшал бы пользовательскую долю. Сохранять детерминизм, независимость от порядка обхода и ограниченную стоимость до300×300; не строить64 полноразмерных шумовых поля или64 сортировки ради повторных карточек.

Территориальные метки задают квоту площади, но не окончательные клеточные biome ID. В Surface-профиле луга и леса сохраняют plains/forest без климатической перекраски всей территории; снежные территории сохраняют снежное ядро. `landscapeBiome` и локальные контексты различают рельеф внутри остальных типов. `deriveBiomes` добавляет берега, поймы и предгорья; у Surface берег ограничен `min(coastWidth,max(1,floor(min(width,height)/32)))`, локальная пойма и окрестность гор — одной клеткой. Это отдельные контексты; переходные среды между территориями используют весь `transitionWidth`0–12. `landscapeEcotones` строит кольца расстояния и применяет только полные кольца, не затрагивающие более35% площади соответствующего типа; берега, поймы и cliffs защищены. Горы переходят в предгорья, снег — в тундровую кромку, пустыня — в savanna/cold-desert, болото — в floodplain, вулканические области — в badlands. Лес/луг не получают дополнительного зелёного переходного цвета. `secondaryBiome/transitionStrength` сохраняют сведения о соседнем контексте, но не создают RGB-градиент. Согласовывать material с изменённым biome; источники проверяют окончательный biome клетки, не территориальную квоту.

В `atlas-water.mjs` профильная ветка фильтрует малые озёра, выбирает разнесённые истоки при достаточном дождевом стоке и ведёт основные цепи по существующему ациклическому `flowTo` через озёра до моря, границы или слияния. Лимит истоков растёт с размером карты и `rivers`; при minSide>=100 возможны короткие низинные рукава, возвращающиеся ниже в ту же сеть. `riverWidth` расширяет исходное ядро с ограничениями высоты и стока, не расширяя новые рукава повторно. Пресная вода статична: head=max(seaLevel+.04,filledElevation+.035), глубина rounded(clamp(head−bed,0,1)). После навигации bed хранится в heightmap, elevation может быть настилом моста. Параметр lakes выбирает впадины, а не неполное заполнение. Не описывать это как динамическую гидродинамику и не переносить профильные изменения в ветку без профиля без отдельной проверки.

`biomeCardsControls` в `Web/HTML/ui/controls.mjs` создаёт повторяемые сворачиваемые карточки. UI-only `biomeCardDrafts` хранит сырые поля отдельно от канонического `generation.landscape.biomes`; функции `biome-card-drafts.mjs` восстанавливают, проверяют и подтверждают карточку атомарно по стабильному ID. Внутренняя «Добавить» расположена над «Удалить биом»: новая карточка до неё отсутствует в recipe, изменённый тип подтверждённой карточки сохраняет прежнее активное значение до «Добавить», а процент фиксируется отдельно по change/Enter. После подтверждения кнопка показывает «Добавлен»; изменение типа вновь разрешает подтверждение, корректный процент активной карточки применяется автоматически. Общий renderer обеих страниц задаёт25% или меньший остаток. biomeDraftLimit резервирует подтверждённые доли и большие видимые черновики в целых десятых процента, исключая ID редактируемой карточки. Динамический max и повторная проверка при клике ограничивают ввод доступной долей. Успешное подтверждение и удаление активной карточки передают regenerate:true через renderer и generationDraftChanged в штатную generate(). Для пути landscape.baseBiome generationDraftChanged сразу вызывает generate() после фиксации нового значения в recipe, без отдельной кнопки и без изменения карточек. Это одинаково для landscape/hexlandscape, с готовой картой и без неё. При фиксации percent обработчик сверяется с активным процентом независимо от совпадения binding.token после input. Он передаёт в confirmBiomeDraft подтверждённую карточку с новым процентом, сохраняя прежний тип, затем publish(true,true). Enter вызывает change; одинаковое повторное значение генерацию не запускает. Наличие активной карточки проверяется по ID в recipe, поэтому её неподтверждённые изменения не мешают удалению. При удалении последней активной карточки генерация получает пустой biomes. Открытие/ввод/удаление UI-черновика остаются черновыми действиями. Ошибка неподтверждённого поля не блокирует «Создать карту» и не меняет бюджет долей. Черновики и раскрытие сохраняются в UI-сессии; импорт, reset и undo/redo восстанавливают список из рецепта. Карточки расположены под базовым биомом, внешняя кнопка добавления — после списка. Набор UI-черновика вызывает только сохранение рабочей сессии; подтверждение, фиксация активного процента и удаление активной карточки меняют рецепт. Ни одно из этих действий не запускает генерацию по input/change или таймеру; публичного поля confirmed нет. Новая основа создаётся через `generate-base` по «Создать карту», смене базового биома, успешной внутренней «Добавить», фиксации активного процента или удалению активной карточки. Явная программная операция `landscape-rebuild` доступна через JS/HTTP/CLI и Worker, но не вызывается редактором карточек автоматически. `app/landscape-rebuild.mjs` допускает только изменения профиля при прежних mode, seed и остальных настройках, сохраняет catalog, sources, transitions и edits, проверяет весь кандидат и отклоняет конфликт атомарно. Именованный проект автоматически не перезаписывается. `applyTerrainField` очищает secondaryBiome/transitionStrength только в клоне клетки с явным biome override, без скрытого пересчёта соседей.

Береговая QA: `tools/verify-coastlines.mjs` сравнивает исходные маски на реальных provider-derived seed, square/hex и50/100/200/300. Крупные заливы должны сообщаться с внешним морем; закрытое озеро не считается заливом. Метрики считают также на уменьшенных в2/4 раза масках, чтобы отличать региональную форму от клеточного шума; связность, морская рамка, площадь и пригодная толщина проверяются отдельно. Численные показатели не заменяют просмотр материального и биомного отображения. Изолированная проверка интерфейса — `node tools/verify-surface-browser.mjs --coastlines`, переносимой копии — `node tools/verify-surface-portable.mjs --coastlines`. Эти команды создают отдельные coastlines/coastline отчёты и не используют пользовательскую working-session; фактические результаты указываются только после запуска.


Морские основы coast/islands/continent используют coastErosion integer0..100/default50 как параметр непрерывного берегового потенциала. На нуле coast имеет ровный берег, islands — гладкие отдельные островные ядра, continent — округлённый прямоугольник; на максимуме добавляются нерегулярные бухты, заливы и выступы. После потенциала выполняется тот же связный квотный рост; не заменять точный landPercent шумовым threshold. Ключ кеша включает coastErosion. Для land поле не влияет на геометрию. Общие квоты, отдельные островные ядра и пригодная толщина сохраняются; регулярная гребёнка, одинаковые тонкие пальцы и осевые зигзаги не являются детализацией берега.

В континентальном потенциале e=coastErosion/100, степень Lp-контура p=8−4e³. Региональная деформация растёт с e, локальные выступы с e^1.5, криволинейные морские долины с e⁴, мягкий непериодический внешний морской пояс с e⁵. Это позволяет усиливать верх шкалы без искажения нулевого округлённого прямоугольника. После потенциала обязательны прежние точная квота и топологически безопасный рост; форма не зависит от uniformity/биомных карточек. Проверки формы отделяют connected sea-inlet от внутреннего озера и контролируют длинные прямые отрезки и тонкие выступы.

Дополнительные ландшафтные типы описывает LANDSCAPE_ADDITIONAL_BIOMES; LANDSCAPE_BIOMES задаёт семь базовых вариантов. Новый gravel проходит квоты landscape-regions, atlas catalog, общие цвета и обе схемы профиля/context. cityPercent в settlement request требует одинаковых defaults, normalize, UI и generation/native schemas. Не красить planning.unassigned в городские площади: целые компактные микрорайоны и общий бюджет обязательны. Кривая высот находится в общем cellColor и не меняет генерацию.

applyLandscapeShallows в atlas-biomes выводит shallow-water из реальных waterDepth и расстояния до сухого берега; он меняет только biome/material. Это морской контекст, не наземная процентная карточка и не новая физика воды. Проверки включают100/300 и обе топологии, берег/подводную отмель/глубокую воду, неизменность суши и runtime.
