# VlandGenerator

Standalone map utility. No game code, parent-project imports, external runtime packages, CDN or absolute development paths. Node 20+; no install. User-authorized optional JSON Schema QA uses an external Python environment; see docs/SCHEMA_QA.md. UI and API use the same document and editor operations. Each mode is a separate page and provider loaded on demand. Generation works in a terminable worker. Never overwrite an existing project without checking its revision. Named projects save only explicitly. The current browser session autosaves all tabs/modes to one bounded .run/working-session.json; a new session after all tabs close clears it. Never add timestamped autosaves or working snapshots. Keep snapshots immutable; store edits as explicit overrides. Validate generated and edited navigation separately. Dungeon connectors default to 1–3 cells; explicit corridor settings allow 1–24 with validated open widths. Never describe tile connectivity as arbitrary-engine physics or a navmesh.

Read README.md, docs/USER_GUIDE.md, docs/API.md, docs/LLM_GUIDE.md, docs/EXTENDING.md and work-status.json. Run node --test, test JS/HTTP/CLI and browser at desktop/360px, then verify a copy in an unrelated folder.

Public editor/content contract is schema 4 only. Do not add legacy formats, aliases or migrations without explicit authorization. Geometry is separate from catalog/sources. Six content categories: resources, flora, fauna, objects, items, events. Protect manually authored sources and source fixtures. Source distribution and runtime planning must be deterministic, revision-checked, budgeted and atomic. Keep content/ independent of app/, engine/, DOM and Node. Use tools/verify-content.mjs for all-mode and runtime lifecycle integration validation.

Isolation is opt-in via layout.allowDisconnected (or each tier request.layout). Default physical connectivity is mandatory. Explicit protected transportLinks may replace an optional open bridge; never hide missing passages by relaxing validation. Main route remains physically connected. Keep secret gates distinguishable in the authoring view. Automatic distribution must be scoped by category, kind, groupId and selected layers, with independent UI drafts.

Author pairs live in project.transitions and reference fixed once/load source IDs, never global catalog destination IDs. Keep connect/disconnect atomic and validate approach, arrival and return across physical layers. Native links stay protected. Preserve bound manual points on redistribution. Host activates a pair only after both entities are confirmed; resolveTransition does not move the player. Run tests/map-links.test.mjs and the trusted-pointer Web/HTML/qa-map-links.html workflow at desktop/360px after transition changes.

Automatic access: layout.transports configures flat dungeon isolation; world autoTransports configures per-layer limits and weighted types. Teleports stay within a floor; automatic stairs/lifts require real other layers and reserved landings. externalTransports are world-access requirements, never local teleport commands. Validate world geometry, actual links, endpoint reachability and return independently. Do not flood arrival rooms or populate transport cells. Runtime links expose flat layerId/x/y/footprint endpoints. Run automatic-transports tests, the 75-map stress tool, desktop/360px settings QA, HTTP/CLI and portable-copy validation.

Geometry evolution: map-frame Map/Content switch, atomic terrain.stroke, RGBA PNG export, topology square/hex, natural automatic access and separate settlements provider. Keep legend and raster colors shared. Hex coordinates are pointy-top odd-r; navigation, hydrology and scene must agree. Do not claim full city simulation, arbitrary physics or hydrodynamics. All new settings need UI/API/schema parity.

Web layout: Web/index.html is the home page; all other HTML pages live in Web/HTML/ and browser modules/CSS/Worker in Web/HTML/ui/. Windows launchers and their direct controller live in Web/start.cmd, Web/stop.cmd and Web/server-control.ps1. Shared app/content/engine, server.mjs, cli.mjs, data, Markdown and build/verification tools stay at project root. Keep / serving the home page and /api/* unchanged. Page builders must write Web outputs and preserve canonical root URLs, query/hash and documentation links. Run tests/web-layout.test.mjs for layout/HTTP and isolated Windows start/restart/stop checks.

Maintenance: user authorizes removal of verified obsolete documentation, temporary files and unused outputs. Keep at most2 existing rollback copies; do not create a development-history archive. Preserve authored sources, fixtures, current verification inputs, named projects and live .run. Canonical checkpoint is work/CONTEXT_STATE.md; docs/IMPLEMENTATION_STATUS.md describes current behavior, not a chronological changelog. See docs/MAINTENANCE.md.
